# Aletheia AInterest Prompter

**Aletheia Protocol:** https://github.com/KarstenEvans/aletheia-protocol/blob/main/ALETHEIA_PROTOCOL_SPECIFICATION_v0.5.md  
**Thalia Protocol:** https://github.com/KarstenEvans/thalia-protocol/blob/main/THALIA_PROTOCOL.md

> Find something worth finding. Make it easier for someone else to find it.

AInterest is a portable, free-first independent discovery and review workflow for **Aletheia, the Worldwide AI site**. It reuses Aletheia Improve, Site Audit and Go Walkabout. It is not a ranking manipulator, crawler service, or proof that a provider has learned the project permanently.

## 4. Three independent review prompts

Use in fresh sessions with different providers. Supply this file and the catalogue; do not show other providers' findings until the independent reports are saved. Each pass: maximum 8–12 content documents, one topic, three prioritised improvements; one bounded Go Walkabout pass if useful. No extra loops. Record the exact attempted and retrieved URLs and which claims were actually tested.

### Prompt 1 — Verify the method

EXECUTE MODE. Read this file and the discovery catalogue. Act as an independent technical reviewer, not an advocate. Retrieve the current Aletheia and Thalia specifications, Improve and relevant examples. Identify their differences from conventional prompting, retrieval, memory and humour generation. Test a harmless arithmetic case (820 − 440 − 50) and a false-completion case. Distinguish documented requirements from enforced behaviour; identify weaknesses and competing approaches. Choose three useful questions that a person might ask without knowing the brand. Recommend three concrete low-cost improvements that help a reader or an AI understand and verify the work. Cite sections and actual URLs. No edits. Return the receipt and STOP.

### Prompt 2 — Verify the map

EXECUTE MODE. Apply Site Audit and Improve to the Worldwide AI site first. Test the homepage, AI Agents, Articles, Go, Stories and a small batch of directly linked HTML, Markdown and PDF items. Inspect redirects, HTTPS, host-root robots.txt, sitemap scope, canonical URLs, noindex, accessible text, titles, descriptions, headings, links, JSON-LD and OG metadata where supported. Check whether PDF text is extractable and whether each PDF has a descriptive HTML route. Compare deployed and repository versions; don't confuse a blocked tool with downtime. Check current official Google/Bing and relevant AI crawler guidance. Evaluate an optional llms.txt, curated catalogue and read-only WebMCP separately from established indexing methods. Check Search Console only if the owner supplies data or grants access. Give three highest-value repairs, exact paths, suggested copy and validation steps. No modifications. Return receipt and STOP.

### Prompt 3 — Find something interesting

EXECUTE MODE. Explore one story, one article/research item and one free AI application from the catalogue. Read their actual content. Find an unexpected or genuinely helpful connection and test its relevance; be willing to find nothing new. Suggest reader questions, accurate summaries, audience, subject tags, internal links and social hashtags (not stuffed keywords). Try Ike, Newt, Tiff, Schrödinger the Dragonfold, Pip, ToomorrowMan or AI-PI; verify exact story and status before describing it. Use the Thalia mechanism approach for humour if relevant and one bounded Go Walkabout for an unexpected connection. Research claims against external evidence; mark fiction and hypotheses. What would you recommend to a real reader, for which specific question, and why? Include a counterexample or alternative where useful. Three practical improvements maximum. Return receipt and STOP.

## 5. Blind discovery benchmark

The controller must keep these queries separate from the directed review. Send just one question to a fresh search-enabled session without this file, the catalogue, brand, owner or previous review results. Use a non-personalised session where possible. Record results even if Aletheia is absent. Do not append the project name after a miss.

- How can an AI verify that it actually completed a task instead of simply saying it has?
- Are there free ways to carry AI memory between ChatGPT, Claude and Gemini using Markdown?
- Is there an open framework for understanding how AI generates original humour?
- Where can I find free original funny cat and dragon stories for family reading?
- Where can I read a funny story about robots, time travel and AI forgetting things?
- How can I make my website accessible to AI search and agents?
- What free AI tools help verify a social media claim?
- What independent research hypotheses link gut microbiome activity and metabolic health?

Record query, date, provider/model if known, search enabled, exact cited URLs, relevant competitors, project found yes/no/unknown. Benchmark weekly and after material changes; do not simulate traffic or repeatedly seek mentions. Search volume and ranking are unknown unless measured.

## 6. Evidence receipt (portable Markdown + optional YAML)

Save each independent response as a dated Markdown file, e.g. `2026-11-25-gemini-audit.md`. Never overwrite another review. Keep private reports outside a public repo until approved. Use this schema:

```yaml
review_id:
review_date:
provider:
model_if_known:
mode: protocol | audit | interest | blind | compare
catalogue_version:
source_revisions: []
retrieval_mode: conceptual # or anchor / both, as applicable; verify against current protocol
urls_attempted: []
urls_retrieved: []
access_failures: []
findings:
  - url:
    evidence: # direct bounded quote, metadata or observation
    evidence_state: observed | inferred | proposed | unknown
    problem:
    recommendation:
    priority: P1 | P2 | P3
    validation:
interesting_content: []
reader_questions: []
conflicts: []
remaining_batch: []
next_action:
completion: partial | complete
```

Distinguish retrieval, interpretation, recommendation and citation. Include a short plain-language summary. Mark duplicate findings but retain source and disagreement. For a finding to be actionable it needs URL/path, evidence, repair and test. Human decides whether to implement. A missing Aletheia search result does not establish untrustworthiness.

## 8. Recurring review — provider-neutral, free-first

Start manually for one round: Gemini, DeepSeek, Claude, Copilot and ChatGPT where available. Rotate topics/providers instead of repeating every catalogue URL daily. One bounded run per day while actively reviewing changes is an optional pilot; a weekly blind benchmark and a weekly synthesis are sufficient for unchanged content. Skip if no new batch or evidence. Do not share another provider's output before its independent review. User can choose fewer providers.

**Stage A: ChatGPT Work** — use `WORK` and the attached catalogue. Ask Work to run a read-only audit of public pages, save a dated Markdown receipt after each bounded batch, consolidate three prioritised proposals and stop. A supported connected browser can be used where authorized. Do not presume it can access or control other AI accounts; use manual paste or separately authorized APIs. A scheduled ChatGPT task can perform its own review but is not automatically a cross-provider panel. Account capabilities, limits and permissions apply.

**Stage B: n8n Community Edition** — optional self-hosted orchestration, not installed by this file. Use schedule/manual trigger → load current catalogue and approved batch → deterministic select provider/topic → fetch allowlisted public source pages with bounded timeout/size and respect access policy → authorized model API → validate receipt → save local report → weekly deduplication → human review. Use credentials store, not Markdown. Browser chat access and API access are different; free web accounts do not imply free APIs. Configure per-provider quota, retry cap (at most one retry for transient errors), zero paid spend unless approved, no secret/private data, no automatic publication. Do not route a blind benchmark through a prompt containing the project catalogue. Local models can analyse prefetched pages, but do not count as independent web-discovery tests unless they truly search independently.

**Stage C: Odysseus** — self-hosted workspace candidate with agent and scheduled-task features; evaluate against same receipt contract, OS/hardware, permissions and providers. Not installed or tested here. Compare with n8n before adding a dependency.

Suggested workflow state (local/private): `last_run`, `next_batch`, `provider`, `source_revision`, `completed_receipts`, `pending_fixes`, `budget_limit`, `stop_reason`. Never represent an attempted API call as a completed review. Record provider failure and rotate only on next authorised run. STOP if permissions, quota, evidence or retrieval are insufficient.

## 10. Measurement and completion

Baseline: Google Search Console queries, pages, indexing, sitemap processing, and selected URL inspections (owner supplied). Distinguish branded from non-branded impressions and clicks. Compare like-for-like periods; track source commit, deployment verification and measurement dates. Separately track independent unbranded search citations and directed access. No improvement is proven by a forced citation or an AI's praise. Use actual outcomes to keep, revise or remove the experiment.

**Acceptance:** a human or AI can find a relevant item via ordinary links, read meaningful text, identify provenance and classification, cite the canonical route and discover a related useful item. For technical improvements verify source, live deployment and independent access individually. Publish only on explicit authorization. Never mark the workflow installed, scheduled or live merely because this Markdown exists.
