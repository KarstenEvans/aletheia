# Aletheia Discussions: Leave a Dot

**Purpose:** a shared conversation space for Aletheia, the Worldwide AI site, and its connected projects.

**Discussion entrance:** https://github.com/KarstenEvans/aletheia/discussions

Read [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md) before participating. Comments and new posts belong in GitHub Discussions, not directly in project source files.

## Recommended initial categories (create in the GitHub UI)

GitHub Discussions supports up to 25 categories. It supports organising categories within named sections, but not ordinary discussion folders. Start with a small number and expand later:

| Category | Format | Who can start a new thread | Purpose |
| --- | --- | --- | --- |
| 📣 Announcements & Official Threads | **Announcement** | Maintainers only | Official news, pinned prompts and per-project feedback threads. Everyone can reply. |
| 🌟 Leave a Dot | **Open-ended discussion** | Signed-in visitors | Suggestions, new ideas, research connections and cross-project dots. |
| 🧪 Aletheia Go | **Open-ended discussion** | Signed-in visitors | Research suggestions, criticism, new experiments, original evidence. |
| 🧩 Aletheia Apps | **Open-ended discussion** | Signed-in visitors | App feedback, accessibility, improvements and user experience. Include app name. |
| 🎭 Humour Keys & Writer Vibes | **Open-ended discussion** | Signed-in visitors | Submit original humour techniques and writing approaches; do not paste copyrighted routines. |

Later, add Aletheia Learn (Q&A), Aletheia Knowledge, Trust Check, Site Audit or other app-specific categories when volume makes them worthwhile. Use one thread per small app first, or organise by labels rather than creating too many categories.

## Suggested sections once the community grows

- **The Gathering Place**: Announcements, Leave a Dot.
- **The Workshop**: Aletheia Apps, Learn, Site Audit and Trust Check.
- **The Library and Explorers**: Aletheia Knowledge, Aletheia Go.
- **The Theatre and Writers' Guild**: Thalia, Humour Keys, Writer Vibes.

Sections contain categories; the categories contain discussions. They are *not* filesystem paths, and a section is not a restriction on who can post.

## Welcome post (copy into GitHub Discussions)

### 🌳 Welcome to Aletheia: Leave a Dot!

**One tree to link them all. Many minds to question them. And truth to illuminate them.**

Welcome to Aletheia, the Worldwide AI site. We connect knowledge, applications, learning, unusual research directions and considerate humour.

Have you found an interesting dot? A new paper? An app that could be better? A missing connection between two ideas? An error we should correct?

Please share it!

**Suggested format**

- **Project:** Aletheia Go / Apps / Learn / Knowledge / Thalia / Articles / Other.
- **Your dot:** One idea, question, piece of feedback, source or original humour key.
- **Why it matters:** Who would benefit, or what would it help explain?
- **Evidence or link:** An original source if relevant. Otherwise say *hypothesis* or *idea*.
- **What should happen next?** Investigate, discuss, correct, test, or simply enjoy.

We encourage constructive disagreement, attribution, accessibility and fun. Harassment, personal attacks and trolling are not welcome and may be moderated or removed.

The point is not that every dot is true. It is that together we can question and connect them.

**Go Walkabout. From AletheIdea into AIxistence.**

## Moderation and decision handling

- GitHub repository maintainers alone approve changes to published source files.
- Discussion visitors can suggest, criticise and respond; this does not grant file edit permissions.
- When a discussion produces a worthwhile change, a maintainer can turn it into a tracked issue or authorised edit, recording links and evidence.
- A good contribution is not automatically a verified fact. Keep source, hypothesis, opinion and humour distinguished.
- Announcement categories restrict new-thread creation to maintainers but still allow comments from others. Other formats generally let signed-in users start threads.
- Project maintainers should review reports and apply the [Code of Conduct](CODE_OF_CONDUCT.md).
